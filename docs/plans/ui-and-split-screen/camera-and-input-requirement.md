* Each player has their own camera and input mapping
* The **keys** for the input mapping are shared between players - each player has a `:fire` action, but what input _triggers_ this actions is player-dependent (for instance one player uses the keybboard and has it one space and the other on a controller on the X button, or both players have controllers and mapped it on their X buttons, or both use controllers and one player has it mapped to X and the other to Y). Those actions are defined **game-global**: A game configures once which actions are available. Some actions might beed to be universal, so UI works (the four directions, commit, abort).
* Each player has their own camera, so split-screen works. This includes the option for one player being currently in the ingame menu (f.i. browsing their inventory), and one player moving in the game world. At the same time the engine needs the option to interrupt the split-screen and pull both players into a single, screen-wide scene (for instance for cutscenes or game over screens)
* The SceneGraph needs to be shared among players / be unique. Each node needs to update once, so NPCs or the game world moves along indepedent from the number of players
* Ideally there is an implicit/default/easy setup for the first player, so in a scenario with just one player there is little to no additional setup overhead.
