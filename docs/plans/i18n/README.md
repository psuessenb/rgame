## Verdict

**Rewrite `Engine::I18n`'s internals, turn `CachedLabel` into `Engine::Text`, and
make a translation key the thing every text-bearing API takes by default.**

- **A game draws a `Text`, never a String it built.**
  `Text.new('hud.score', :score)` is built once, and
  `renderer.text(@score.with(score: @points), 12, 10)` reads it every frame for
  zero objects while nothing changes. It re-resolves when its variables change
  *or* the language does. That resolves the open `CachedLabel` issue by
  generalizing it rather than adding a second object beside it.
- **`label:` on every UI widget is a key.** Hardcoded text is the thing that
  takes extra typing (`Text.literal(name)`), not the other way round.
- **`RGame::Game` finds and loads every `locales/**/*.yml` through the asset
  manager and picks the player's OS language**, so a game writes no i18n setup
  at all. `rgame new` generates a project that already uses it, and specs fail
  on a missing key.
- **Every example moves to keys**, so whatever a reader copies carries the right
  habit.

## Goal

Make translated text the easiest way to put text on screen, from the first file
a new user generates. There is no "add i18n later" migration because there is
never a hardcoded phase. And do it without a per-frame cost.

## The requirement, verbatim

> * i18n should be the default way and the easy way. I want users to use it from
>   the get-go, not writing hardcoded strings first because it's way easier and
>   then later go through the pain of adding i18n in
> * i18n files should be loaded through the asset manager
> * we only need to support languages, not dialects: `de`, but no need for
>   `de_at` etc. Supporting those is nice-to-have, if it's easy to add, go for
>   it. If it makes things complicated or noticeable slower, forget it
> * this is a game engine, so performance needs to be considered
> * I like the Rails I18n format (YAML files with nested keys), if possible use this
> * pluralization via `count` is a must-have feature
> * `%{var}` or another format to include variables is a must-have feature
>
> The plan needs to include:
> * the i18n system itself
> * proper documentation
> * an example (linked from the examples page and global README.md). This is
>   already listed in the `basic-examples.md` - this plan here will write this
>   very example, so it's one in total, not two.
>
> Prefer solutions that make for a better user-experience long-term over
> solutions that cause less work or rewrite today.
>
> Look through the current documentation and plans as well. There is already
> one issue with CachedLabel today (it needs to react to updates from both
> content and language) which waits for this plan to solve, maybe there is more
> hidden.

## Hard constraints

1. **`I18n` and `Text` are engine layer: pure Ruby, headless, never naming
   `RGame::Core`.** `require "rgame"` keeps its zero-graphics property.
2. **An unchanged `Text` read allocates nothing.** It is asserted with
   `spec/support/allocate_nothing_matcher.rb`, the way every other per-frame
   claim in the engine is.
3. **Every byte a game ships is read through the asset manager, including
   finding the locale files.** See decision 5. Nothing in `Engine` globs or
   reads a directory on the game's behalf.
4. ~~**The renderer interface does not change.**~~ **Amended after step 5: the
   renderer's label arguments accept a `to_str` object, and nothing else
   changes.** `renderer.text` and `text_width` take a String or anything with
   `to_str`, so `renderer.text(@title, x, y)` draws a `Text`. `nil`, an Integer
   and every other object are still refused with `TypeError`, in the real
   renderer and the fake alike. See decision 13.
5. **Linux, macOS and Windows stay green.** Language detection is the one piece
   of new C, and the `windows-portability` skill applies to it.
6. **No runtime gem dependency.** YAML is `psych`, a default gem.

## Decisions already taken

These were settled in the question round. They are not up for re-litigation
inside this plan.

1. **The language lives in a global module, `RGame::Engine::I18n`, as today.**
   Language is process state in every engine surveyed, and a global lets a
   `Text` be built in `initialize`, before its node is in any tree. The leak a
   global carries in this codebase is *listeners* (the AudioBus lesson in
   `basic-examples.md`). A `Text` **polls** `I18n.generation` and never
   subscribes, so no listener exists to pin.
2. **The translated string is `Engine::Text`, a generalized `CachedLabel` with
   keyword variables.** `CachedLabel` is renamed and changed rather than joined
   by a second object answering the same question. The name is `Text`, not
   `Label`, because `Label` would collide with a likely future `UI::Label` widget
   inside `module UI`. Variables are keywords, not positionals. A generated
   `with(name:, level:)` costs zero objects (measured), and it turns a forgotten
   or misspelt variable into Ruby's own `ArgumentError: missing keyword`.
3. **A UI widget's `label:` is a translation key.** Text that must not be
   translated is passed as an explicit `Text.literal(...)`. The alternatives, a
   Symbol-as-key or Godot's "an untranslated key shows itself", both leave
   hardcoding as the shorter path, and that fails requirement 1.
4. **Missing keys follow a configurable policy.** The game default shows the
   key. Specs raise: the engine's `spec/spec_helper.rb` and the generated
   project's both set it, and a generated spec checks that every locale has the
   default locale's keys. A missing key found by `rake` is found by the
   developer; one found in the game is found by a player.
5. **Locale files are found by convention and loaded through the asset manager.**
   `RGame::Game` loads every `locales/**/*.yml` under the media root, eagerly and
   in Rails' format (top-level key = locale, so one file may hold several).
   `Game.new(locales:)` overrides the directory. **Discovery goes through the
   asset manager too** (a new `AssetManager#glob`), and the YAML text comes from
   `assets.read`. `I18n` parses a String and never opens a file. The user
   raised a question here: would convention block a future packed asset format,
   for Steam? Answer: *not if both the listing and the read go through the one
   seam*. Steam itself does not require packs. SteamPipe patches loose files at
   ~1 MB chunk granularity, and its pack-file advice (localized changes, stable
   order, per-asset compression, no absolute-offset TOC) constrains a pack
   *writer* rather than the code reading through it
   ([Steamworks: Uploading to Steam](https://partner.steamgames.com/doc/sdk/uploading)).
   So this design adds no new direct file access. The existing obstacles to a
   pack are elsewhere and are recorded in
   [01-current-state.md](01-current-state.md): images, fonts and audio `fopen`
   a path inside C.
6. **CLDR plural categories with built-in integer rules** for en de nl sv da nb
   fi it es pt fr, ru uk pl cs, ja zh ko, ar, plus `I18n.plural_rule` for
   anything else. As in Rails, an explicit `zero:` wins for 0 in every language.
7. **Regional locales are supported: `de-AT` falls back to `de`, then to the
   default.** The chain is computed once per switch and `Text` caches, so the
   per-frame path does not change. `:de_at`, `'de-AT'` and `:'de-AT'` are one
   locale.
8. **Text measurement is not in this plan.** It gets its own plan after this one;
   the trigger in `docs/plans/possible-todos.md` now says so. This plan makes
   sure nothing *caches* a width across a language switch, and the example picks
   slots wide enough for both its languages.
9. **Every example migrates to keys.** Test projects do not: they are games, not
   teaching material.
10. **`RGame::Game` picks the player's language at startup** from
    `SDL_GetPreferredLocales`: the first preferred locale that has a table, else
    the default. Remembering a player's explicit choice stays the game's job
    through `Util::SaveFile`, and the example shows it.
11. **`scope:` is in.** `Text.new('play', scope: 'title_menu')`, and
    `UI::Menu.new(scope: 'title_menu')` so its buttons say `label: 'play'`. The
    other Rails extras (`default:`, lazy lookup, arrays, symbol links) are out
    of the first cut.
12. **Decided without objection in the question round:** the module name
    `RGame::Engine::I18n` stays and its internals are replaced freely; tables
    are compiled at load time; `%{var}` as in Rails, with `%%{` escaping a
    literal; one language per process, not per player; right-to-left text and
    non-Latin fonts are out of scope.
13. **A `Text` is passed to `renderer.text` as it is, through `to_str`.**
    *Taken after step 5, reversing "A `to_str` object passed straight to
    `renderer.text`" in [02-prior-art.md](02-prior-art.md).* Step 5's example
    wrote `renderer.text(@title.to_s, MARGIN, 24)` on three lines in a row, for
    what is the default case. Requirement 1 asks for i18n to be the easy way, and
    passing the variable is easier than calling a method on it. The implicit
    conversion is a real cost, and it was judged smaller than a `.to_s` on every
    translated line.
    It is `to_str`, not a `to_s` on anything: the renderer calling `to_s` would
    silently draw `nil` as `""`, allocate a String per frame for an Integer, and
    draw any other object as `#<Foo:0x…>`. `to_str` keeps each of those a
    `TypeError`. Measured at `951ae37`: `String#to_s` costs 14 ns against 3,454
    ns for one `renderer.text`, so speed never decided it. The rejection's first
    reason no longer held either: since step 3 a `Text` keeps the values of its
    last `with`, and `with` is still how a `Text` with variables is drawn.
14. **A drive run fails on a missing key, and only a drive run does.** *Taken in
    step 7's question round.* The harness sets `I18n.missing` to a callable that
    records the key and returns it, so the run draws what the game draws. It
    exits 1 when a key was recorded and a table was loaded. Driving every example
    in CI from `spec_core` was the alternative. It would catch crashes too, but it
    was not taken. A static spec reading keys out of `main.rb` was rejected: it
    misses keys built at runtime and scopes set in a method.
15. **A sentence around a translated name is one key with the name as a
    variable.** *Taken in step 7's question round.* `"Chosen: %{item}"` plus
    `items.save: Save`, rather than one key per whole sentence. A translator
    writes each name once, and a game's HUD needs this shape. It is the wrong
    shape for a language that inflects the name after the label. The examples
    only use a label-style "Label: name", where that does not arise.
16. **Step 7's strings stay identical, except for a plural that changes the
    English.** *Taken in step 7's question round.* The drive diff is the
    acceptance, so a wrong key cannot hide behind an intended change. Today
    the one exception is `pathfinding`'s "1 waypoints". Counters that read
    "label: N" gain no plural forms, because English shows none.
17. **`Game/NoLiteralText` flags a String literal passed to `text` or
    `text_width`** in `examples/` and `lib/`. *Taken in step 7's question round;
    resolves open question 4.* It catches the form a reader copies. A table of
    Strings passes it, and that limit is stated rather than chased.

## Open questions

1. **Does `scope` inherit down the tree, like player ownership, or stay a `Menu`
   option?** Inheriting would let any subtree (a HUD, a dialog) set a scope once.
   *Resolved in step 3:* a `Menu` option, not inherited. It reaches only labels
   and captions a button built from keys; a `Text` handed to a button keeps its
   own scope. See step 3's landed note.
2. **How does `OptionButton` name its captions?** A `display:` returning a key
   or a `Text` covers `menu_navigation`'s `'on'`/`'off'` and `"#{percent}%"`.
   What the *default* display is for Symbol values is open. *Decided while
   writing step 3, against `examples/menu_navigation`.* Step 0 found that YAML
   reads unquoted `on`/`off` as booleans and the loader refuses them, so
   whatever keys this picks must be quoted in the table. *Resolved in step 3:*
   `OptionButton::DISPLAY` reads a Symbol value as its own key and makes any
   other value a literal of its `to_s`; a String `display` returns is a key.
3. ~~**Where do the examples' locale files live?**~~ **Settled in step 5's
   plan: beside each `main.rb`**, loaded with
   `locales: File.join(__dir__, 'locales')`. All 24 examples share
   `examples/assets/` as their media root, so a shared `examples/assets/locales/`
   would load every example's keys into every example, and keys namespaced per
   example would hold only while each example remembered its namespace. See step
   5 in [04-roadmap.md](04-roadmap.md); `examples/localization` is built this way.
4. ~~**Should a RuboCop cop flag a String literal passed to `renderer.text` or
   `label:`?**~~ **Settled in step 7's question round: yes, for `text` and
   `text_width`, in `examples/` and `lib/`.** `label:` is left out: its literal
   is a key. See decision 17. Generated projects do not load the house cops,
   so it reaches only this repository.
5. **Does `SDL_GetPreferredLocales` need `SDL_Init` first, and what does it
   return under Xvfb and on the macOS and Windows runners?** *Resolved in step
   2:* it needs no init, so it is the module function
   `RGame::Core.preferred_locales`. CI returned `[]` on Linux and `["en-US"]` on
   macOS and Windows. See step 2's landed note.
6. **Does `I18n` need a snapshot, so a game's spec suite can restore its tables
   without re-parsing them?** Step 4's generated `spec_helper` re-loads every
   table before every example: 0.03 ms for the generated table, 8 ms for 1,000
   keys. A `snapshot`/`restore` pair would make that constant, since compiled
   tables are frozen. *Waits on a game whose suite finds the reload slow;
   non-blocking.*

## What this does not deliver

- **Text measurement and buttons sized to their labels**: the next plan.
- **Right-to-left text, shaping, and non-Latin scripts.** The shipped font covers
  Latin, Greek and Cyrillic. A CJK game needs a font the engine does not ship,
  and nothing here selects a font per locale.
- **Per-player language in split-screen.**
- **Translating images, audio or other assets per locale.**
- **Rails' `default:`, lazy lookup, array values and symbol links.**
- **Migrating `test_projects/`.**
- **A packed asset format.** This plan only avoids adding a new obstacle to one.
